# 2026-06-08 工作日志

## A↔B Node 连接修复 ✅

### 问题
A端（Windows）→ B端（Ubuntu）Node 持续 disconnected，无法远程访问 B端 workboard。

### 根本原因
1. A端 `openclaw.json` 中 `autoApproveCidrs` 位置错误（放在了 `gateway.auth` 下而非 `gateway.nodes.pairing`）
2. B端 Node service 未安装 → systemd `start-limit-hit` 失败
3. Pairing 认证需要 auto-approve CIDR 或手动 approve

### 修复步骤
1. **修正配置路径**：将 `autoApproveCidrs: ["192.168.31.0/24"]` 移到 `gateway.nodes.pairing`
2. **B端安装 Node service**：`openclaw node install && openclaw node start`
3. **重启两端 Gateway**：使新配置生效
4. **验证连接**：`openclaw nodes status --json` 确认 B-Soldier-Node connected

### 关键教训
- `autoApproveCidrs` **正确路径是 `gateway.nodes.pairing`，不是 `gateway.auth`**
- Node service 安装后必须手动启动（systemd user service）
- pending pairing request 5 分钟过期，autoApproveCidrs 可跳过此窗口

### workboard 远程访问限制
- workboard 数据存储在 Gateway 本地 SQLite
- CLI `workboard list` 无 `--url/--token` 等远程参数
- Gateway 不暴露 workboard HTTP RPC endpoint
- **解决方案**：SSH 到 B端直接执行 `openclaw workboard list --json`
