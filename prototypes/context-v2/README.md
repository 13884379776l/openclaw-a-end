# Context Protocol V1.0 — 多 Agent 协作协议

**生效时间：** 2026-05-22  
**最终版本：** V1.0（双方确认）

## 定位

**不是取代**原有的 A→B 通讯文件协议，而是**补充**——旧协议管"说什么"，Context Protocol 管"怎么做"。

| 协议 | 用途 | 类比 |
|------|------|------|
| 旧通讯协议 | 文本消息交换 | 发邮件 |
| Context Protocol | 任务分配 + 进度追踪 | 项目管理 |

## 核心场景

指挥官说："做个 GPU 测试"

| 阶段 | 旧协议 | Context Protocol |
|------|--------|----------|
| 收到 | 收到文件 | 记录任务 |
| 拆解 | 直接做 | 拆解步骤 |
| 执行 | — | 子 agent 独立执行 |
| 汇报 | 发结果 | 汇报进度 + 最终结果 |

## 命名规范

```
<日期>_M<N>_<类型>_<简述>.md
```

- **日期**：`YYYY-MM-DD`
- **编号**：`M001`, `M002`...（每日重置）
- **类型**：`task`, `status`, `review`, `sync`, `notify`
- **简述**：中文，不超过 20 字

**示例：**
```
2026-05-22_M001_task_GPU测试.md
2026-05-22_M002_status_通讯同步.md
```

## sub-steps 规则

| 子步骤数量 | 方式 | 说明 |
|------------|------|------|
| ≤3 条 | sub-steps/ 列表 | 简单任务直接列表 |
| >3 条 | 独立子文件 + 列表索引 | 复杂任务拆文件 |

**列表格式：**
```markdown
## sub-steps/
- [ ] 2026-05-22_M001_步骤一.md
- [ ] 2026-05-22_M002_步骤二.md
```

## 同步机制

| 时间 | 说明 |
|------|------|
| 10:00 GMT+8 | 上午同步（状态更新、任务分发） |
| 18:00 GMT+8 | 晚间同步（结果汇总、计划确认） |

## 子 Agent 隔离验证

| 指标 | 不拆分 | 拆分 | 结论 |
|------|--------|------|--|
| 父 session token 增长 | 4,000 | ≈200 | ⬇️ 95% |
| 上下文膨胀 | 进入父 | 完全隔离 | ✅ |
| 推理速度 | 90K 后变慢 | 独立不受拖慢 | ✅ |

## 知识库结构

```
prototypes/context-v2/
├── README.md          ← 本协议
├── context/
│   ├── active-task.md ← 当前活跃任务
│   ├── decisions.md   ← 决策记录
│   ├── sub-steps/     ← 子步骤
│   ├── subagent-results/ ← 子 agent 结果
│   └── ab-bridge/    ← A/B 端桥接文件
```

## 通讯优先级

1. **b2a.md / a2b.md** — 核心通道（单文件汇总）
2. **context-v2/** — 补充（结构化任务数据）

两者不冲突，配合使用。

## 关键决策记录

| 日期 | 决策 | 原因 |
|------|------|------|
| 2026-05-22 | 编号用 M 前缀 | 区分通讯消息和普通文件 |
| 2026-05-22 | 简述用中文 | A/B 端中文母语，降低理解成本 |
| 2026-05-22 | sub-steps ≤3 用列表 | 简单任务不需额外文件 |
| 2026-05-22 | sub-steps >3 用独立文件 | 复杂任务需要追踪和引用 |
| 2026-05-22 | 知识库用 prototypes/context-v2/ | A/B 端统一位置 |
| 2026-05-22 | 生效时间：本周内 | 后续通讯统一按 V1.0 |
